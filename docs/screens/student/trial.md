# Webトライアルの申込（studentアプリ・公開画面）

## 概要

- アプリ: `student`
- パス: `/trial`、受付完了は `/trial/complete`（どちらもログイン不要。ログイン中でも開ける）
- 対象ロール: 未登録の利用者（Webトライアルを申し込む人）
- 目的: Webトライアルを申し込む。申し込むと、入力したメールアドレスにパスワード設定の案内（招待）が届き、
  パスワードを設定した日から14日間、アプリのトレーニングとコーチとのライブセッション1回を利用できる。
  利用者に見せる期間の表記はコーポレートサイトに合わせて「2週間」（`WEB_TRIAL_PERIOD_LABEL`。画面・招待メール）。

## この画面に来る経路

- コーポレートサイト（gabbyacademy.com）のトライアルの申込ボタンからリンクする（`https://blueprint.gabbyacademy.com/trial`）。
  アプリ内からの導線は無い。
- コーポレートサイトからは**別タブのリンク**（`target="_blank" rel="noopener"`）で開く。iframe での埋め込みはできない
  （全アプリで他のサイトへの埋め込みを禁止している。`packages/lib/security/frameHeaders.ts`）。

## 画面の構成・状態

| 状態 | 表示内容 | 発生条件 |
|---|---|---|
| 入力 | 見出し「無料体験のお申し込み」（ブラウザのタブも同じ）と、段階表示（① 入力 → ② 確認 → ③ 完了。確認・完了の画面にも出す）、無料体験の内容の要約（2週間アプリのトレーニングを使える・コーチとのマンツーマンのライブセッション1回・料金はかからない〔お支払い情報の入力は不要〕と、2週間はパスワードを設定した日から数える旨。アプリで提供していない特典〔AIスピーキング診断等〕は載せない）、入力欄、同意のチェック、「入力内容を確認する」ボタン | 画面を開いた時・確認画面で「修正する」を押した時（入力内容は残る） |
| 確認 | 見出し「入力内容のご確認」、入力内容の一覧（未入力の任意項目は「未入力」）、「コーチに表示されるお名前」（ローマ字の 名 姓）と、お名前の使い道の案内（「アプリでの表示や各種のご案内に使用します」。用途が増える可能性があるため、レポート・変更方法等の具体的な用途は書かない）、CAPTCHA、「修正する」「申し込む」ボタン | 入力画面で誤りなく「入力内容を確認する」を押した時 |
| 受付完了（`/trial/complete`） | 「お申し込みを受け付けました」と、案内のメールを送ったこと・届かない場合は迷惑メールのフォルダを確かめるよう促す案内、「このページは閉じていただいて構いません」、コーポレートサイトのトップへのリンク「Gabby のサイトへ」（同じタブ）。「閉じる」ボタンは置かない（`window.close()` は開き方・ブラウザによって効かないため） | 送信に成功した時（申込の種類によらず同じ表示。下記「申込の種類」）。URL を直接開いた時も同じ表示（個人情報は出さない） |

### 画面の移り方・ブラウザバック

| 操作 | 動き |
|---|---|
| 入力 →「入力内容を確認する」 | URL は `/trial` のまま確認画面に切り替え、履歴を1つ積む |
| 確認画面でブラウザバック | 「修正する」と同じく入力画面へ戻る（入力内容は残る） |
| 確認画面で再読み込み | 空の入力画面になる |
| 確認 →「申し込む」（成功） | 確認画面の履歴を `/trial/complete` に置き換えて移る |
| 受付完了で再読み込み | 受付完了のまま |
| 受付完了でブラウザバック | 確認画面には戻らず、空の入力画面（`/trial`）になる（二重送信を防ぐ） |

- 画面を切り替えたら、画面の先頭から表示する。

## 入力欄

| 項目 | 必須 | 入力の決まり |
|---|---|---|
| メールアドレス | ○ | 200文字以内・メールアドレスの形式。小文字にそろえて保存する |
| 姓・名 | ○ | 各20文字以内。姓と名を左右に並べる（狭い画面でも2列） |
| 姓（ローマ字）・名（ローマ字） | ○ | 各20文字以内・半角の英字（空白・`'`・`-` も可）。姓・名の下に左右に並べる |
| 業種・職業 | ○ | 会社員（事務・管理）/ 会社員（営業・販売）/ 会社員（技術・IT）/ 医療・福祉 / 教育 / 公務員 / 自営業・フリーランス / 学生 / 主婦・主夫 / その他 から選ぶ |
| 業種・職業（その他） | 「その他」を選んだ時だけ表示・必須 | 50文字以内 |
| Gabby をどこで知りましたか？ | ○ | Facebook / X（旧Twitter）/ Instagram / YouTube / 検索エンジン（Google・Yahoo!など）/ 知り合い・友人から / その他 から選ぶ（旧システムの申込フォームを引き継ぎ、Instagram を追加） |
| Gabby をどこで知りましたか？（その他） | 「その他」を選んだ時だけ表示・必須 | 50文字以内 |
| お住まいの地域のタイムゾーン | ○ | タイムゾーンのマスタ（`com_m_timezone`）から選ぶ（UTCからの時差を併記。既定は日本）。一覧は7件強の高さで、右側のスクロールバーでスクロールする。本登録時にユーザーのタイムゾーンに設定する |
| 国・都市 | | 50文字以内 |
| ご要望・ご質問 | | 1000文字以内 |
| 個人情報保護方針に同意する | ○ | 「個人情報保護方針」は https://gabbyacademy.com/privacy/ へのリンク（新しいタブ）。同意しないと送信できない。同意の日時は申込の日時として扱う |
| CAPTCHA（Cloudflare Turnstile） | ○ | 確認画面に置く（トークンは約5分で期限が切れ1回しか使えないため、送信の直前に通す）。「人間であることを確認します」のチェック。完了前に送信すると「『人間であることを確認します』のチェックを完了してください。」 |

- 入力の誤りは各欄の下に表示し、確認画面へ進まない。サーバーでも同じ決まりで確かめる。
- 氏名の使い道: 本登録時に、姓・名とローマ字から正式な氏名（トレーニングレポート等の書面に載せる。admin のユーザー管理「正式氏名」と同じもの）を作る。
  画面に出す名前（コーチも見る）はローマ字の「名 姓」（例: Taro Yamada）にする。申込者へのメールの宛名・管理者への通知は「姓 名」（例: 山田 太郎 様）。
  登録済みのアドレスからの再申込では、正式な氏名・画面の名前は変えない。

## 送信結果

| 結果 | 表示・挙動 | 発生条件 |
|---|---|---|
| 成功 | 受付完了の表示。申込の種類に合わせてメールを送り、管理者へ通知する（下記） | — |
| CAPTCHA の失敗 | フォーム下に「確認に失敗しました。お手数ですが、もう一度お試しください。」。CAPTCHA は取り直しになる | サーバーでの確認に失敗した場合（秘密鍵が未設定の環境を含む） |
| 受付の失敗 | フォーム下に「お申し込みを受け付けられませんでした。時間をおいて、もう一度お試しください。」 | DB の処理に失敗した場合 |

### 申込の種類（画面の表示は同じ。登録の有無が外から分からないようにする）

| 種類 | 条件 | 申込者へのメール | その他 |
|---|---|---|---|
| 新規 | 未登録・招待の無いアドレス | パスワード設定の案内（件名「Webトライアルのお申し込みありがとうございます」。リンクの有効期限は3日） | 招待を作る（所属は固定の顧客「Webトライアル」） |
| 再申込 | トライアルの招待が本登録前（期限切れを含む） | 同じ案内を再送（リンク・有効期限を出し直す） | 申込の内容を最新の入力に更新し、回数を増やす |
| 登録済みのアドレス | すでにアカウントがある | ログインの案内（ログイン・パスワード再設定へのリンク） | 招待は作らない |
| 招待中のアドレス | トライアル以外の招待（管理者が作った招待）が本登録前 | 送らない | 既存の招待には触れない。サポート窓口が個別に対応する |

- どの種類でも、管理者全員にアプリ内の通知「Webトライアルの申込」を出し、サポート窓口へ申込の内容のメール（日英併記）を送る
  （宛先は環境ごとの設定。dev・staging は開発者、本番は support@gabbyacademy.com）。
- 同じアドレスから2分以内に続けて送信された場合は、何もせず受付完了を表示する（二重送信・連打の対策）。
- メールの送信に失敗しても申込は受け付ける（申込は記録され、管理者への通知は届く）。

## 本登録（パスワード設定）の後

- 招待のリンクから [招待からの本登録](../common/invite.md) と同じ画面でパスワードを設定する。
- 本登録の時点で、その月（日本時間）のトライアルの契約（1日〜翌月14日、ライセンス数100。無ければ自動で作る）を使い、
  本登録の日から14日間（日本時間の暦日）のライセンスと、ライブセッション1回のチケットを発行する。ライセンス数を超えても発行する。
- トライアル終了後の扱い（ログイン時の案内等）は未定。
