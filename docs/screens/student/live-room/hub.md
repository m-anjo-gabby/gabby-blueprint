# ライブセッション・ホーム（studentアプリ）

## 概要

- アプリ: `student`
- パス: `/live-room`
- 対象ロール: 生徒
- 目的: 専属コーチとの個別ライブセッションについて、対応が必要な事項（振替候補・コーチ未選択・未予約）、
  次回の予定、契約の回数の内訳、今後の予定、履歴を1画面で確認・操作する。個別セッションに関する操作の起点となる画面。

## この画面に来る経路

- 画面下部のボトムタブ（モバイル）／左サイドナビ（PC）の「ライブセッション」タブから遷移する（全生徒に表示）。
- [カレンダー](../calendar.md)・[専属コーチを探す](../coach-matching.md)の戻るボタンから戻ってくる。
- 実施済みセッションの各カードから[セッション結果画面](./session-result.md)へ、次回のセッションの
  「入室する」ボタンから[通話画面](./call-room.md)へ、それぞれ遷移する。

## 画面の構成

タブは使わず、優先度の高い順に1本のスクロールで並べる。

1. **ヘッダー** — 画面タイトルと「カレンダー」ボタン。契約（チケット）を複数保持している生徒のみ、
   その下に対象契約の切り替えセレクトボックス（現在有効な契約があれば既定で選択、無ければ最新の過去契約）
2. **対応が必要です**（該当がある時だけ表示。現在の契約を選択中のみ）— 振替候補カード、コーチ未選択の案内、
   未予約の案内
3. **次回のセッション**（現在の契約で今後の予定がある場合）。カード下部に前回のセッション結果への導線を置く。
   今後の予定が無い場合は、前回のセッション結果への導線を単独のカードとして表示する
4. **契約の状況**（過去の契約を選択中は「契約の実績」）— 回数の内訳バーとコマごとの状況
5. **今後の予定**（次回以降の予定・承認待ちの予約リクエストがある場合）
6. **履歴** — 既定は実施済みのみ。「キャンセルも表示」スイッチで、生徒・コーチ本人によるキャンセルを同じ時系列に重ねて表示

契約の切り替えはURLのクエリ（`/live-room?contract=<ticket_id>`）で行い、選択中の契約のデータを
サーバーで取り直す（切替中は内容を半透明にする）。キャンセル・予約リクエスト・振替候補への応答などの
操作後も、画面全体のデータをサーバーから取り直す。

## ライブセッション付き契約が無い場合（紹介画面）

ライブセッション付き契約を一度も保持したことがない生徒（アプリのみ契約）には、ハブの代わりに
ライブセッション紹介画面を表示する（過去に契約があった生徒は履歴確認のためハブを表示する）。

| 要素 | 内容 | 操作した時の挙動 |
|---|---|---|
| ヒーロー | キャッチコピーとプラン概要 | — |
| 特長 | 専属コーチ・自主トレとの連携・アプリで完結、の3項目 | — |
| ご利用の流れ | 「コーチを選ぶ」「予約する」「入室する」の3ステップ | — |
| 申し込み案内（法人でご利用の方） | 常時。案内文「ご所属先のご担当者様、または運営のサポート窓口までご相談ください。」と、その下に「サポート窓口：support@gabbyacademy.com」 | 「サポート窓口にメールで相談する」ボタンで、件名「ライブセッションの利用について」を入れたメール作成画面を開く |
| 申し込み案内（個人でご利用の方） | 常時。案内文「ライブセッション付きプランへの変更をご検討ください。」 | 「個人向けプラン・料金を見る」ボタン（ゴールド）で、公式サイトの料金ページ（`https://gabbyacademy.com/price`、個人向け）を別タブで開く |

申し込み案内は、法人・個人の両方を常に併記する（現在の利用者は法人契約が中心のため法人を先に表示）。
所属テナントの種別（`com_m_client.client_type`）による出し分けは未実装。アプリのみ契約にはチャットを
開放していないため、法人向けの相談導線はメールのみとしている（チャット開放時に「運営に相談する」を追加予定）。

文言・導線は `apps/student/constants/liveSessionIntro.ts` で一元管理する。サポート窓口のアドレスは
`packages/lib/contact.ts`（招待メール等のテンプレートと共通）で定義する。

## 表示要素・操作

| 要素 | 表示条件・内容 | 操作した時の挙動 |
|---|---|---|
| 「カレンダー」ボタン | 常時（ヘッダー右） | `/calendar` へ遷移 |
| 契約セレクトボックス | 契約（チケット）を2件以上持つ生徒のみ | URLの `?contract=` を切り替え、その契約の内訳・履歴を表示する |
| 振替候補カード | 自分宛の未回答・未失効の振替候補がある場合、キャンセル1件につき1枚。「◯◯コーチの都合でキャンセルになりました」、元の予定（取り消し線）、候補（最大3件、ラジオ選択）、回答期限と残り時間 | 候補を1つ選んで「この日時で予約する」を押すと振替のセッションが作成される。「候補以外の日時を希望する」は確認ダイアログの後に候補をまとめて見送り、続けて予約リクエストダイアログを開く（見送り時、コーチへの通知は送られない） |
| コーチ未選択の案内 | コーチ未選択（マッチングリクエスト未送信・否認後）のコマがある場合。週2回契約では「週2回のうち1コマの専属コーチが未選択です」、そのコマに割り当てられる回数も表示 | 「コーチを選ぶ」で `/coach-matching` へ遷移。全コマ選択済み（承認待ちを含む）の場合、この画面から専属コーチ選択への導線は表示しない |
| 未予約の案内（「日時が決まっていないセッションがn回あります」） | 未予約の回（下記の内訳の「未予約」）が1回以上あり、予約可能なコマがある場合 | 「日時をリクエスト」で予約リクエストダイアログを開く（[calendar.md](../calendar.md)の予約リクエストダイアログと同一仕様） |
| 次回のセッション | 直近の予定1件。日時・コーチ、開始までの残り時間 | 開始予定時刻の5分前から「入室する」が有効になり、[通話画面](./call-room.md)（`/live-room/[sessionId]`）へ遷移する。それまでは「開始5分前から入室できます」と表示し押せない。「この回をキャンセル」でセッションキャンセルダイアログを開く（[calendar.md](../calendar.md)と同一仕様） |
| 前回のセッション（「前回のセッション・9月22日(火)」＋宿題の状況＋「結果を見る」） | 現在の契約を選択中で、実施済み（未参加を除く）のセッションがある場合。対象は開始日時が最も新しい1件。次回のセッションがあればそのカードの下部に、無ければ単独のカード（コーチ名も表示）として出す。宿題の状況は3通り: 宿題未登録＝「宿題の登録はありません」／本文のみ（チェックリストなし）＝「宿題あり：本文の1行目」／チェックリストあり＝「宿題 2/3 完了」（すべて完了なら「宿題はすべて完了しています」） | タップで[セッション結果画面](./session-result.md)へ遷移する（宿題の再確認・前回の内容の振り返り用） |
| 契約の状況：回数の内訳 | 「実施済み n / 総数回」と内訳バー・凡例。現在の契約では 実施済み／直前キャンセル（返還なし）／予約済み／調整中（予約リクエスト・振替候補の回答待ち）／未予約／コーチ未選択 に分ける（実施済み・予約済み・未予約は0回でも表示、他は1回以上の時のみ）。過去の契約では 実施済み／直前キャンセル／未実施 | 表示のみ |
| 契約の状況：コマの一覧 | 現在の契約のみ。コマごとに曜日・時刻（生徒のタイムゾーンに変換）と担当コーチ。承認待ちは「（承認待ち）」、未選択は「専属コーチ未選択」。週1回契約ではコマ番号を出さない | 表示のみ |
| 今後の予定 | 次回以降の予定と、コーチ未応答の予約リクエスト（「承認待ち」バッジ）を日時順に表示。初期5件 | 予定の「キャンセル」でキャンセルダイアログ、リクエストの「取り下げる」でリクエストを取り下げる。「さらにn件を表示」で5件ずつ追加 |
| 履歴 | 既定では実施済み（完了・早期終了・未参加）のみを開始日時の降順で表示。各行は日時、ステータスバッジとコーチ名（2段目）。初期10件 | 実施済みの行はタップで[セッション結果画面](./session-result.md)へ遷移。「さらにn件を表示」で10件ずつ追加 |
| 「キャンセルも表示（n件）」スイッチ | 選択中の契約に、生徒・コーチ本人によるキャンセルが1件以上ある場合のみ（履歴の見出し右）。既定はオフで、画面を開くたびにオフに戻る。契約終了・コーチ交代等の運用都合のキャンセルは件数・表示とも対象外 | オンにするとキャンセルを同じ時系列に控えめな色で表示し、理由があれば「理由：〜」を出す（キャンセル行は操作なし）。切り替えるたびに表示件数は10件に戻る |

### 回数の内訳の算出

- 実施済み・予約済み・直前キャンセルは、選択中の契約（`ticket_id`）の `com_t_session` から数える
  （直前キャンセル＝`status=cancelled` かつ `ticket_refunded=false`）。
- 未予約は、コーチ選択済みのコマの `fn_schedule_shortfall()` の合計（予約リクエストRPCの可否判定と同じ）。
  このうち承認待ちの予約リクエストと、回答待ちの振替候補の件数分を「調整中」として差し引く。
- コーチ未選択は、未マッチング・承認待ちのコマについて、承認時と同じ均等割り
  （`total_sessions / weekly_frequency`、余りはコマ番号の小さい順に1回ずつ）で見積もる。
- バーの分母は総数（`total_sessions`）。管理者がコマ別の目標数を引き上げて内訳の合計が総数を超える場合は、合計を分母にする。

## 状態

| 状態 | 表示内容 | 発生条件 |
|---|---|---|
| 契約の切り替え中・操作後の再取得中 | 画面の内容を半透明にし操作不可にする | 契約セレクトボックスの変更、各操作の完了後 |
| 予定なし | 「予定されているセッションはありません」 | 現在の契約で、今後の予定・承認待ちリクエスト・対応が必要な事項がいずれも無い場合 |
| 実施済みなし | 「実施済みのセッションはまだありません」。キャンセルがある場合は「キャンセルの記録は「キャンセルも表示」で確認できます」を併記 | 表示対象（スイッチがオフなら実施済みのみ）が0件の場合 |
| 予約リクエストの取り下げ中 | 「取り下げる」ボタンがスピナー表示になり非活性化 | 取り下げ処理の実行中 |
| 振替候補の応答中 | 押したボタンがスピナー表示になり、カード内の他の操作は非活性化 | 承認・見送り処理の実行中 |
| 振替候補の期限切れ | 承認・見送りともエラーのトースト | 画面表示後に回答期限（提案から24時間）を過ぎてから操作した場合 |
