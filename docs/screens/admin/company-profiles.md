# 会社情報（adminアプリ）

## 概要

- アプリ: `admin`
- パス: `/company-profiles`
- 対象ロール: 管理者
- 目的: 書面（PDF）の発行元として印字する会社情報（会社名・住所・税務登録番号・ロゴ）を、法人ごとに管理する。
  法人は日本法人（`GABBY_JP`）とバンクーバー法人（`GVT_CA`）の2つで、どの書面をどちらの名義で発行するかは
  コードで決まっている（下表）。画面から法人を追加・削除することはできない。

| 書面 | 発行元の法人 |
|---|---|
| 生徒向けトレーニングレポート（admin `/training-reports`） | 日本法人 |
| コーチ向け月次支払通知書（coach） | バンクーバー法人 |
| コーチの請求書（INVOICE、admin） | バンクーバー法人 |

## この画面に来る経路

- サイドバーメニューの「システム設定」グループ内「会社情報」から遷移する。

## 画面の構成

1. **ヘッダー** — 画面タイトル、説明文
2. **法人ごとの編集カード**（日本法人 → バンクーバー法人の順。広い画面では2列）
   - 見出し（法人名）と、その法人が発行元になる書面の説明
   - 会社名（英語）・会社名（日本語・任意）・住所・税務登録番号（任意）の入力欄と「保存」ボタン
   - 会社ロゴのプレビューと「ロゴ画像を変更」ボタン

## 表示要素・操作

| 要素 | 表示条件・内容 | 操作した時の挙動 |
|---|---|---|
| 会社名（英語） | 必須 | 「保存」で反映 |
| 会社名（日本語・任意） | 任意。案内「設定した場合、日本語の書面（トレーニングレポート）で英語の社名と併記します。」 | 「保存」で反映（空欄は未設定として保存） |
| 住所 | 必須。複数行。案内「改行した位置で、書面上も改行して印字されます。」 | 「保存」で反映 |
| 税務登録番号（任意） | 任意。入力例は日本法人が適格請求書発行事業者の登録番号、バンクーバー法人がカナダGST/HST登録番号 | 「保存」で反映。現在は請求書（INVOICE）にのみ、設定した場合に印字される |
| 「保存」ボタン | 常時表示（保存中は処理中の表示） | 入力した4項目を保存し、「会社情報を更新しました」を表示する。前後の空白は取り除いて保存する |
| 会社ロゴ | 設定済みならプレビュー画像、未設定なら「未設定」 | 表示のみ |
| 「ロゴ画像を変更」ボタン | 常時表示（アップロード中は処理中の表示） | 画像（PNG / JPEG / SVG / WebP）を選ぶとすぐにアップロードし、プレビューを差し替えて「ロゴ画像を更新しました」を表示する。保存先のファイル名は法人ごとに分ける（もう一方の法人の書面のロゴは変わらない） |

## 状態

| 状態 | 表示内容 | 発生条件 |
|---|---|---|
| 取得失敗 | 「会社情報の取得に失敗しました。DDL/DMLが反映されているかご確認ください。」 | 会社情報マスタの取得に失敗した、または行が1件も無い場合 |
| 必須項目が空 | 「会社名（英語）と住所は必須です。」（トースト） | 会社名（英語）または住所を空にして保存した場合 |
| 権限なし | 「この操作を行う権限がありません。」（トースト） | 管理者以外が保存・ロゴの変更を実行した場合（サーバーアクション側で確認） |
| 保存失敗 | 「会社情報の更新に失敗しました。」（トースト） | DBの更新に失敗した場合 |
| ロゴの保存失敗 | 「ロゴ画像のアップロードに失敗しました。」／「ロゴ画像は保存されましたが、パスの更新に失敗しました。」（トースト） | Storage へのアップロード、または会社情報マスタのロゴのパスの更新に失敗した場合 |
