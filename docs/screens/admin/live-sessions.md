# ライブセッション管理（adminアプリ）

## 概要

- アプリ: `admin`
- パス: `/live-sessions`（子画面: 実施記録 `/live-sessions/records`）
- 対象ロール: 管理者
- 目的: 顧客・生徒・契約を選択して、その生徒のライブセッション（コーチとの個別レッスン）の
  予約状況・担当コーチ割当状況を確認し、生徒・コーチに代わって「セッションのキャンセル」
  「未消化チケットでの予約」「担当コーチの交代」「コーチとの直接マッチング」を行う。
  あわせて、開始済みのセッションの実施結果（コーチの End Session の記録）を記録・修正する
  （生徒・契約単位はこの画面の実施済みタブ、全生徒・全コーチ横断は子画面の実施記録）。

生徒・コーチ自身が行う予約リクエスト／承認フロー（[個別予約リクエスト・振替候補フロー](../../../testing/e2e/specs/booking/individual-booking-and-reschedule.md)）とは異なり、
この画面での操作はいずれも承認ステップを挟まず即座に確定する管理者専用の代理操作である。

## この画面に来る経路

- サイドバーの「ライブセッション管理」から遷移する。ダッシュボードにはこの画面へのカードはない。
- 実施記録へは、この画面の見出しの右の「実施記録」ボタンから遷移する（実施記録の戻るリンクでこの画面へ戻る）。

## 画面の構成

1. **対象の選択カード** — 顧客→生徒→契約（チケット）の3段階の絞り込み
2. **ライブセッション予約状況カード** — 選択した契約について、定期スケジュール枠の状況と
   セッション一覧（今後の予定／実施済み／変更履歴のタブ）を表示
3. **セッションキャンセルダイアログ**（代理操作）
4. **セッション予約ダイアログ**（代理操作）
5. **コーチ直接マッチングダイアログ**（代理操作）
6. **セッション数個別調整ダイアログ**
7. **実施結果の記録・修正ダイアログ**（実施記録の一覧と共用）

## 表示要素・操作

| 要素 | 表示条件・内容 | 操作した時の挙動 |
|---|---|---|
| 顧客セレクト | 常時表示（検索式） | 選択すると生徒セレクトの選択肢が読み込まれ、生徒・契約以降の選択状態はリセットされる |
| 生徒セレクト | 顧客を選択済みの場合のみ活性 | 選択すると、その生徒が保有するライブセッション付き契約（現在・過去とも）が読み込まれる。現在有効な契約があれば自動選択、無ければ一覧の先頭を自動選択する |
| 契約（チケット）セレクト | 生徒が1件以上のライブセッション付き契約を保有する場合のみ表示 | 「現在の契約」または「過去の契約（参照のみ）」のラベル付きで契約期間を表示。選択するとその契約の定期スケジュール枠・セッション一覧が読み込まれる |
| 定期スケジュール枠の一覧 | 稼働中・一時停止・終了済みの枠を全て表示（「第n枠: 曜日 開始〜終了（基準のタイムゾーン）」「担当コーチ」「総セッション数」「ステータスバッジ」）。セクション冒頭に「全n枠中 稼働n枠・未割当n枠」のサマリーを表示 | 稼働中の枠にセッション未割当がある場合は「未割当n件」バッジも表示 |
| 「セッションを予約」ボタン | 稼働中の枠に未割当のチケット枠（`shortfall`）がある場合のみ表示（過去契約では非表示） | セッション予約ダイアログを開く |
| 「セッション数を調整」ボタン | 稼働中の枠に表示（過去契約では非表示） | セッション数個別調整ダイアログを開く |
| 「コーチ交代」ボタン | 稼働中の枠に表示（過去契約では非表示） | 確認ダイアログの上で、その枠の担当を終了する |
| 未割当枠（週n回契約でまだマッチングが成立していない枠番号）の「直接マッチング」ボタン | 過去契約では非表示 | コーチ直接マッチングダイアログを、対象の枠番号で開く |
| セッション一覧タブ（今後の予定／実施済み／変更履歴） | 契約を選択している場合に表示 | 各タブでそのカテゴリのセッションを一覧表示。「実施済み」タブには、確定済みに加えて、終了予定を過ぎても記録されていないセッション（「未記録」バッジ）も並ぶ。「変更履歴」タブは、原因を問わず全てのキャンセル済みセッションを表示する（監査目的のため、本人操作のキャンセルのみに絞る生徒・コーチ側の一覧より広い） |
| セッション一覧の「外部のZoom」「通話の記録と違う」の印 | 外部のZoomで実施と記録された行、アプリ内の通話で実施と申告した結果が入退室ログからの推定と違う行 | 操作なし |
| セッション一覧の「結果を記録」「結果を修正」ボタン | 開始済みで、未記録（終了予定超過）・確定済み・コーチの欠席・通信トラブル等で実施できなかった行のみ。過去契約では非表示（実施記録から修正する） | 実施結果の記録・修正ダイアログを開く |
| セッション一覧の「キャンセル」ボタン | 実施予定（scheduled）のセッションのみ、かつ過去契約でない場合に表示 | セッションキャンセルダイアログを開く |

## 生徒・コーチへの通知

この画面の操作（直接マッチング・セッションの予約・キャンセル・コーチ交代・セッション数の調整）では、生徒・コーチへアプリ内通知もメールも送らない。
必要な連絡は運営が個別に行う（[notification/mail-dispatch.md](../../../testing/e2e/specs/notification/mail-dispatch.md)）。

## 定期スケジュール枠のステータス

- 「稼働中」「一時停止」「終了済み」の3種類。表示は`com_m_lesson_schedule.status`にそのまま対応する

## セッションキャンセルダイアログ（代理操作）

- 入力項目: 「チケットを返還する（未割当扱いに戻し、再予約可能にする）」チェックボックス
  （初期値はON）、理由（任意・内部メモ）
- 生徒・コーチ自身のキャンセルと異なり、開始12時間前ルールなどの自動判定は行われず、
  チケットを返還するかどうかを管理者が都度明示的に指定する
- 実行すると対象セッションが即座にキャンセルされる

## セッション予約ダイアログ（代理操作）

- 対象は「稼働中の定期スケジュール枠のうち、未割当のチケット枠があるもの」
- 入力項目: 日付、開始時刻（30分単位の選択式）。終了時刻は枠の所要時間から自動計算される
- 承認ステップを経由せず、`admin_book_session_direct`により即座にセッション行が作成される
- サーバー側で確かめるのは、開始が現在より後であることと、コーチ・生徒の既存の予定と重ならないこと（重なる場合はエラー）。
  コーチが登録した空き時間（Weekly Availability）の内側かどうかは確かめない（直接マッチングの割合の基準・24時間ルールと同じく、
  アドミンの例外措置として縛らない）。画面の注記で、空き時間の外でも予約できるため事前にコーチへ確認するよう案内する
- 日時を変更したい場合は「キャンセル（チケット返還あり）→ 改めて予約」の2操作で行う運用になっており、
  ワンステップでの日時変更（旧・アドミン専用の振替RPC）は廃止されている

## コーチ直接マッチングダイアログ（代理操作）

- 対象は「週n回契約のうち、まだコーチが割り当てられていない枠番号」
- 入力項目: コーチ（検索式セレクト）、枠番号、曜日、開始時刻（30分単位）。終了時刻はレッスン実施時間
  （25分）から自動計算される。曜日・開始時刻は**生徒のタイムゾーン**（プロフィールの設定）の時刻として扱う
  （生徒の申請と同じ。夏時間の切り替えをまたいでも生徒側の時刻は変わらない）
- 生徒のリクエスト・コーチの承認を経ずに、その場でマッチングを成立させ、セッションも自動で予約される
  （24時間ルールの対象外）
- 成立と同時に生徒×コーチのチャットルームが用意され、コーチから挨拶メッセージが自動送信される
  （[チャットルーム一覧の「マッチング成立時の自動開設」](./chat/list.md#マッチング成立時の自動開設)参照）
- サーバー側で確かめるのは、コーチ・生徒の既存の予定との重なり。重なる回・開始済みの回は飛ばして作り、残りは未予約になる。
  契約期間内の全ての回が重なる場合だけエラーになる（`NO_BOOKABLE_SESSION`）。コーチが登録した空き時間（Weekly Availability）の
  内側かどうかは確かめない（画面の注記で、事前にコーチへ確認するよう案内する）
- コーチ交代の後は、交代前に同じ枠で使った回（実施済み・返還なしのキャンセル）を差し引いた回数を総セッション数にする
  （契約の回数を超えない。[specs/admin/live-session-management.md](../../../testing/e2e/specs/admin/live-session-management.md) 4a）

## セッション数個別調整ダイアログ

- 対象は稼働中の定期スケジュール枠のみ（過去契約・一時停止・終了済みの枠では操作不可）
- 入力項目: 新しい総セッション数（現在値より大きい値のみ）、理由（必須・内部メモ）
- `com_m_lesson_schedule.target_sessions`（コマ別の総セッション数）のみを引き上げる。
  契約全体の総セッション数（`total_sessions`）は変更しない、あくまで正当な理由がある
  追加予約の例外措置
- 実行しても新しいセッションが自動生成されるわけではない。引き上げにより
  「未割当n件」（shortfall）が増えるため、既存の「セッションを予約」または
  「直接マッチング」から管理者が個別に日時を指定して追加予約する
- 変更理由の履歴はDBには保持されない（アプリケーションログにのみ記録）

## 実施結果の記録・修正ダイアログ

- 対象: 開始済みのセッションのうち、未記録のまま終了予定を過ぎたもの・確定済み・コーチの欠席・通信トラブル等で実施できなかったもの
  （開始前のコーチのキャンセル・生徒のキャンセル・代理キャンセル・自動キャンセルは対象外）
- 開いた時に、入退室ログの根拠（同時に在室した時間等）と記録・修正の履歴（誰がいつどの結果にしたか・チケットの消化/返還・理由）を取得して表示する
- 入力項目: 実施結果（実施完了／生徒の都合で早く終了／生徒の欠席／コーチの欠席／通信トラブル等で実施できなかった）、
  実施方法（結果が実施完了・早期終了・欠席の場合のみ。アプリ内の通話／外部のZoom）、理由（必須・社内メモ）。初期値は現在の記録
  （未記録の場合は入退室ログからの推定）
- 保存すると `admin_correct_session_outcome` で確定する。チケットは結果に合わせて消化・返還の差分を自動で調整する
  （実施完了・早期終了・欠席は消化、コーチの欠席・通信トラブル等は返還して振替の対象にする）
- 生徒・コーチへの通知は送らない。返還済みの回を実施完了等へ直しても、その回で予約済みの振替はそのまま残る
- 同じ結果のまま保存し直すと「アドミン確認済み」になり、実施記録の「要確認」から外れる（理由に確認した内容を書く）
- 承認済みの月次レポートの件数は変わらない（承認時の件数を固定保存しているため）

## 実施記録（`/live-sessions/records`）

開始済みのライブセッションの実施結果を、全生徒・全コーチを横断して確認・修正する一覧（アドミンの一覧部品 `components/list/`）。

| 要素 | 表示条件・内容 | 操作した時の挙動 |
|---|---|---|
| 検索欄 | 生徒名・コーチ名の部分一致 | URLの `q` を変えて取り直す |
| 絞り込み | 要確認（すべて／要確認のみ）・月（今月から12か月、日本時間）・コーチ・結果（未記録／実施完了／早期終了／欠席／コーチの欠席／通信トラブル等）・実施方法 | URLのクエリ（`review` / `month` / `coach` / `result` / `via`）を変え、1ページ目に戻る。「条件をクリア」で全条件を外す |
| 一覧の列 | 開始日時（日本時間）・生徒・コーチ・結果（バッジ＋「外部のZoom」「通話の記録と違う」「アドミン確認済み」の印）・メモ（コーチの理由） | — |
| 「要確認」バッジ | 未記録・早期終了・欠席・外部のZoom・推定と違う・コーチの欠席・通信トラブル等のうち、アドミンがまだ修正・確認していない行 | — |
| 「記録」「修正」ボタン | 全行 | 実施結果の記録・修正ダイアログを開く。保存後は一覧を取り直す |

対象は、開始済みで「未記録（終了予定超過）・確定済み・開始後に記録したコーチの欠席・通信トラブル等」のセッション
（開始前のコーチのキャンセルは、上の画面の変更履歴タブで確認する）。

## 担当コーチ交代（確認ダイアログ）

- 対象の枠を終了させる操作。実行すると、まだ実施されていない今後のセッションはキャンセルされるが、
  実施済みのセッション結果・チャット・宿題は削除されない
- 終了後、生徒は同じ枠に対して新しいコーチへ改めてリクエストできるようになる（または管理者が
  「直接マッチング」でその場で新しいコーチを割り当てられる）

## 状態

| 状態 | 表示内容 | 発生条件 |
|---|---|---|
| 生徒未選択 | 契約欄に「生徒を選択してください」（非活性セレクト） | 顧客のみ選択済みの場合 |
| 契約なし | 「この生徒はライブセッション付き契約を保有していません」 | 選択した生徒がライブセッション付き契約を1件も持たない場合 |
| スケジュール枠・セッション読み込み中 | スピナー表示 | 契約選択直後のデータ取得中 |
| 枠なし | 「まだマッチングが成立していません」 | 定期スケジュール枠・未割当枠のいずれも0件の場合 |
| セッションなし | 各タブに「該当するセッションはありません」、または一覧全体で「セッションはまだありません」 | 該当カテゴリのセッションが0件の場合 |
| 過去契約選択時 | 「過去契約（参照のみ）」バッジを表示し、キャンセル・予約・コーチ交代・直接マッチング・結果の記録/修正の操作ボタンを一切表示しない | 選択した契約が現在有効でない場合（参照専用） |
| 読み込み中（画面遷移直後） | 汎用の骨組み（実施記録は表の骨組み） | `live-sessions/loading.tsx`・`live-sessions/records/loading.tsx` |
