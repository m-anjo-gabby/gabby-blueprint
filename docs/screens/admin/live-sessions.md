# ライブセッション管理（adminアプリ）

## 概要

- アプリ: `admin`
- パス: `/live-sessions`
- 対象ロール: 管理者
- 目的: 顧客・生徒・契約を選択して、その生徒のライブセッション（コーチとの個別レッスン）の
  予約状況・担当コーチ割当状況を確認し、生徒・コーチに代わって「セッションのキャンセル」
  「未消化チケットでの予約」「担当コーチの交代」「コーチとの直接マッチング」を行う。

生徒・コーチ自身が行う予約リクエスト／承認フロー（[個別予約リクエスト・振替候補フロー](../../../testing/e2e/specs/booking/individual-booking-and-reschedule.md)）とは異なり、
この画面での操作はいずれも承認ステップを挟まず即座に確定する管理者専用の代理操作である。

## この画面に来る経路

- サイドバーの「ライブセッション管理」から遷移する。ダッシュボードにはこの画面へのカードはない。

## 画面の構成

1. **対象の選択カード** — 顧客→生徒→契約（チケット）の3段階の絞り込み
2. **ライブセッション予約状況カード** — 選択した契約について、定期スケジュール枠の状況と
   セッション一覧（今後の予定／実施済み／変更履歴のタブ）を表示
3. **セッションキャンセルダイアログ**（代理操作）
4. **セッション予約ダイアログ**（代理操作）
5. **コーチ直接マッチングダイアログ**（代理操作）

## 表示要素・操作

| 要素 | 表示条件・内容 | 操作した時の挙動 |
|---|---|---|
| 顧客セレクト | 常時表示（検索式） | 選択すると生徒セレクトの選択肢が読み込まれ、生徒・契約以降の選択状態はリセットされる |
| 生徒セレクト | 顧客を選択済みの場合のみ活性 | 選択すると、その生徒が保有するライブセッション付き契約（現在・過去とも）が読み込まれる。現在有効な契約があれば自動選択、無ければ一覧の先頭を自動選択する |
| 契約（チケット）セレクト | 生徒が1件以上のライブセッション付き契約を保有する場合のみ表示 | 「現在の契約」または「過去の契約（参照のみ）」のラベル付きで契約期間を表示。選択するとその契約の定期スケジュール枠・セッション一覧が読み込まれる |
| 定期スケジュール枠の一覧 | 稼働中・一時停止・終了済みの枠を全て表示（「第n枠: 曜日 開始〜終了」「担当コーチ」「ステータスバッジ」） | 稼働中の枠にセッション未割当がある場合は「未割当n枠」バッジも表示 |
| 「セッションを予約」ボタン | 稼働中の枠に未割当のチケット枠（`shortfall`）がある場合のみ表示（過去契約では非表示） | セッション予約ダイアログを開く |
| 「コーチ交代」ボタン | 稼働中の枠に表示（過去契約では非表示） | 確認ダイアログの上で、その枠の担当を終了する |
| 未割当枠（週n回契約でまだマッチングが成立していない枠番号）の「直接マッチング」ボタン | 過去契約では非表示 | コーチ直接マッチングダイアログを、対象の枠番号で開く |
| セッション一覧タブ（今後の予定／実施済み／変更履歴） | 契約を選択している場合に表示 | 各タブでそのカテゴリのセッションを一覧表示。「変更履歴」タブは、原因を問わず全てのキャンセル済みセッションを表示する（監査目的のため、本人操作のキャンセルのみに絞る生徒・コーチ側の一覧より広い） |
| セッション一覧の「キャンセル」ボタン | 実施予定（scheduled）のセッションのみ、かつ過去契約でない場合に表示 | セッションキャンセルダイアログを開く |

## 定期スケジュール枠のステータス

- 「稼働中」「一時停止」「終了済み」の3種類。表示は`com_m_lesson_schedule.status`にそのまま対応する

## セッションキャンセルダイアログ（代理操作）

- 入力項目: 「チケットを返還する（未割当扱いに戻し、再予約可能にする）」チェックボックス
  （初期値はON）、理由（任意・内部メモ）
- 生徒・コーチ自身のキャンセルと異なり、開始12時間前ルールなどの自動判定は行われず、
  チケットを返還するかどうかを管理者が都度明示的に指定する
- 実行すると対象セッションが即座にキャンセルされる

## セッション予約ダイアログ（代理操作）

- 対象は「稼働中の定期スケジュール枠のうち、未割当のチケット枠があるもの」
- 入力項目: 日付、開始時刻（30分単位の選択式）。終了時刻は枠の所要時間から自動計算される
- 承認ステップを経由せず、`admin_book_session_direct`により即座にセッション行が作成される
- 画面上の注記のとおり、コーチの空き時間内である必要がある（違反時はサーバー側でエラーになる）
- 日時を変更したい場合は「キャンセル（チケット返還あり）→ 改めて予約」の2操作で行う運用になっており、
  ワンステップでの日時変更（旧・アドミン専用の振替RPC）は廃止されている

## コーチ直接マッチングダイアログ（代理操作）

- 対象は「週n回契約のうち、まだコーチが割り当てられていない枠番号」
- 入力項目: コーチ（検索式セレクト）、枠番号、曜日、開始時刻（30分単位）。終了時刻はレッスン実施時間
  （25分）から自動計算される
- 生徒のリクエスト・コーチの承認を経ずに、その場でマッチングを成立させ、セッションも自動で予約される
  （24時間ルールの対象外）
- コーチの空き時間・既存の予定との重複はサーバー側で自動チェックされる。重複する場合は
  「このコーチは指定の時間帯に既に別の予定があります」等のエラーが表示される

## 担当コーチ交代（確認ダイアログ）

- 対象の枠を終了させる操作。実行すると、まだ実施されていない今後のセッションはキャンセルされるが、
  実施済みのセッション結果・チャット・宿題は削除されない
- 終了後、生徒は同じ枠に対して新しいコーチへ改めてリクエストできるようになる（または管理者が
  「直接マッチング」でその場で新しいコーチを割り当てられる）

## 状態

| 状態 | 表示内容 | 発生条件 |
|---|---|---|
| 生徒未選択 | 契約欄に「生徒を選択してください」（非活性セレクト） | 顧客のみ選択済みの場合 |
| 契約なし | 「この生徒はライブセッション付き契約を保有していません」 | 選択した生徒がライブセッション付き契約を1件も持たない場合 |
| スケジュール枠・セッション読み込み中 | スピナー表示 | 契約選択直後のデータ取得中 |
| 枠なし | 「まだマッチングが成立していません」 | 定期スケジュール枠・未割当枠のいずれも0件の場合 |
| セッションなし | 各タブに「該当するセッションはありません」、または一覧全体で「セッションはまだありません」 | 該当カテゴリのセッションが0件の場合 |
| 過去契約選択時 | 「過去契約（参照のみ）」バッジを表示し、キャンセル・予約・コーチ交代・直接マッチングの操作ボタンを一切表示しない | 選択した契約が現在有効でない場合（参照専用） |
