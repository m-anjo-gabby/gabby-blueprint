# グループセッションのシリーズ（adminアプリ）

## 概要

- アプリ: `admin`
- パス: `/calendar-events/series`（一覧）、`/calendar-events/series/new`（作成。`?from=<seriesId>` で「このシリーズを元に作成」）、`/calendar-events/series/[seriesId]`（詳細）
- 対象ロール: 管理者（カレンダーイベント管理を利用できるロール）
- 目的: グループセッションを企画（シリーズ。例: 「10月の発音グループセッション」「10月のビジネス英語ミニセッション」）ごとに、
  シリーズ名・説明（企画の紹介・その月のテーマ等）と複数の回をまとめて管理する。翌月分は新しいシリーズとして作る。
- シリーズの回はシリーズの作成画面（シリーズと回をまとめて登録）と、シリーズ詳細の「回をまとめて追加」でだけ作る。カレンダーイベント管理（[list.md](./list.md)）の「新規登録」は単発のイベント専用で、
  シリーズの付け外しはできない（シリーズの回の編集画面ではシリーズ名を読み取り専用で表示し、「シリーズで管理」でこの画面へ移る）。

## この画面に来る経路

- カレンダーイベント管理のヘッダーの「シリーズ管理」（一覧）。
- カレンダーイベント管理の一覧で、シリーズの回のタイトルの下の「シリーズ: <シリーズ名>」、または回の編集ダイアログの「シリーズで管理」（詳細）。

## シリーズ一覧

| 要素 | 表示条件・内容 | 操作した時の挙動 |
|---|---|---|
| 「カレンダーイベント管理へ戻る」 | 常時 | `/calendar-events` へ |
| 「新規シリーズ」 | 常時 | シリーズの作成画面（`/calendar-events/series/new`）へ |
| 一覧の行 | シリーズ名・回数（論理削除を除く）・次回の開始（これから始まる直近の回の開始日時。日本時間。無ければ「予定なし」）。新しく作った順 | 行全体（またはシリーズ名・「回の管理・詳細」ボタン）でシリーズの詳細へ |
| 空の一覧 | 「シリーズはまだありません。」 | — |

## シリーズの作成

シリーズ（シリーズ名・説明）と回を1回の操作でまとめて登録する。回の無いシリーズは作らない（回は1件以上必須）。

| 要素 | 表示条件・内容 | 操作した時の挙動 |
|---|---|---|
| 戻るリンク | 新規は「シリーズの一覧へ戻る」、元にした場合は「元のシリーズへ戻る」 | 一覧／元のシリーズの詳細へ |
| 見出し | 新規は「シリーズの新規作成」、元にした場合は「このシリーズを元に新しいシリーズを作成」と、引き継いだ内容の説明 | — |
| シリーズ | シリーズ名（必須）・説明（任意） | — |
| すべての回に共通する設定・回ごとの設定 | 「回をまとめて追加」と同じ入力欄（下記） | — |
| 「キャンセル」 | 常時 | 戻るリンクと同じ遷移先へ |
| 「シリーズを作成する（n回）」 | 常時 | シリーズとすべての回を1つのトランザクションで登録し（1件でも失敗したらシリーズも作らない）、「シリーズを作成しました」と表示してそのシリーズの詳細へ移る |

- **新規の初期値**: シリーズ名・説明は空、共通設定は既定値（生徒全体・参加URLなし・非公開）、回は今日の 21:00〜21:30 の1行。
- **このシリーズを元に作成の初期値**: シリーズ名は元のシリーズ名の末尾に「（コピー）」、説明は元のまま。共通設定は「回をまとめて追加」の初期値と同じ規則で元の回から作る。
  回は元の回（開始日時の順）と同じ数だけ用意し、時刻・担当コーチを引き継ぐ。日付は最初の回が元の最後の回の1週間後になるようずらし、
  回同士の間隔は元のまま（例: 元が 10/7・10/14・10/21 なら 10/28・11/4・11/11）。内容・説明は空。元のシリーズに回が無い場合は新規と同じ1行。
  `from` のシリーズが見つからない場合は新規として開く。
- バリデーション: シリーズ名が必須。回の入力は「回をまとめて追加」と同じ。

## シリーズ詳細

| 要素 | 表示条件・内容 | 操作した時の挙動 |
|---|---|---|
| 「シリーズの一覧へ戻る」 | 常時 | `/calendar-events/series` へ |
| 見出し | シリーズ名・回数。説明があれば下に表示 | — |
| 「編集」 | 常時 | シリーズ名・説明を編集する |
| 「このシリーズを元に作成」 | 常時 | シリーズの作成画面（`/calendar-events/series/new?from=<seriesId>`）へ。下記「このシリーズを元に作成」の初期値で開く |
| 「削除」 | 常時 | 確認の上でシリーズを削除する。各回は削除されず、単発のイベントとして残る（`series_id` は外れる） |
| 「回をまとめて追加」 | 常時 | 下記のダイアログを開く |
| 回の一覧 | シリーズの回（開始日時の順）。表示・操作はカレンダーイベント管理の一覧と同じ（参加者、編集、削除）。シリーズ名の表示は省く | 「参加者」は `?from=series` 付きで参加者・アナウンス管理へ（戻るリンクがこのシリーズの詳細になる。[participants.md](./participants.md)） |

### 回をまとめて追加

- **すべての回に共通する設定**: 配信対象（生徒全体／顧客指定。顧客指定は対象顧客が必須）、「回ごとに参加URLを設定する」、参加URL、公開する。
  - 「回ごとに参加URLを設定する」がオフの場合は、共通の参加URLをすべての回に設定する。オンの場合は共通の欄を隠し、各回に参加URLの欄を出す
    （オフに戻した場合、各回に入力したURLは登録に使わない。隠れた欄の入力はバリデーションの対象外）。
  - 参加確認はグループセッションのため常に有効で登録する（その旨を表示）。
- **回ごとの設定**: 日付（日本時間）・開始時刻・終了時刻（任意。開始時刻以前なら翌日の時刻とみなす）・内容（タイトル、必須）・説明（任意）・
  参加URL（「回ごとに参加URLを設定する」がオンの場合だけ。任意）・担当コーチ（複数選択）。
- **初期値**: 配信対象・公開はシリーズの最後の回を引き継ぎ、1週間後の同じ時刻・同じ担当コーチの1行を用意する（内容・説明は空）。回が無い場合は今日の 21:00〜21:30。
  参加URLは、シリーズの回のURLがすべて同じ（空を含む）ならオフでそのURL、回ごとに違えばオンで各回は空欄（会議のURLは回ごとに発行されることが多いため引き継がない）。
  「回を追加（1週間後）」で直前の行の1週間後の行を足し（回ごとの参加URLは空欄）、「この回を外す」で行を消す（1行は残す）。
- 「n件を登録する」ですべての回を1つのトランザクションで登録する（1件でも失敗したら登録しない）。登録後はダイアログを閉じ、「n件の回を登録しました」と表示する。
- バリデーション: 日付・開始時刻・内容が必須、参加URL（使う側の欄）はURL形式、顧客指定の場合は対象顧客が必須。

## 状態

| 状態 | 表示内容 | 発生条件 |
|---|---|---|
| 読み込み中 | 一覧・詳細は表形式、作成画面は一覧形式の汎用の骨組み | `series/loading.tsx`・`series/[seriesId]/loading.tsx`・`series/new/loading.tsx` |
| シリーズが見つからない | 「シリーズが見つかりませんでした。」と一覧へ戻るリンク | 削除済み・存在しない `seriesId` |
