# 用語集

サービス・契約・教材の言葉の正本。画面の文言・メール・設計の文書・ステークホルダー向けの資料は、ここの「使う言葉」で書く。
DB・コードの名前（`contract_type` 等）は変えずに残してよく、対応を「DB・コード」の列に書く。

- **状態**: 確定 / 仮置き（MTG で確認するまでの置き方）/ 未決（候補だけを書く）。仮置き・未決のものは §5 に確認の項目として並べる。
- 言葉の揺れを見つけたら、ここに足してから直す。決まった言葉を変える場合も、先にここを直す。

## 1. サービスの全体像

契約は「区分」と「利用形態」の組み合わせで決まる。

| | アプリのみ | ライブセッション付き |
|---|---|---|
| **通常の区分**（名前は未決） | 汎用教材で自主トレーニング | ＋ライブセッション（汎用教材） |
| **Blueprint** | 汎用教材＋コーパス教材で自主トレーニング | ＋ライブセッション（コーパスから作ったスプリント・ダイアログも使う） |

- システム上の区分の違いは、コーパス教材があるかどうかだけ。Blueprint の契約には、システムの外の提供物（コーパスの作成・コーチングのフォローアップ）も含まれる。
- ビデオ・スピーキングテスト等の機能は、どちらの区分でも使える。法人ごとに割り当てる汎用教材が違うことはある（§3「公開範囲」）。
- Blueprint は法人に限る。通常の区分は法人・個人の両方（Webトライアルは通常の区分）。
- 区分は契約期間の途中で切り替えない。通常の区分の契約が終わった後、次の契約から Blueprint にする。そのため区分は顧客ではなく契約の属性になる（DB の列はまだ無い）。
- 現行システム（Gabby）からの移行者は、原則として通常の区分の契約にする。

## 2. サービス・契約

|---|---|---|---|---|---|
| **Gabby** | サービス全体・アプリの名前 | Gabby | Gabby Blueprint（アプリ名として） | 画面・メールの「Gabby Blueprint」（`apps/admin/messages/ja.json` の `appName` 等） | 仮置き |
| **Blueprint** | ブランド。顧客の IP 資産から作るコーパス教材が付く、プレミアムの契約の区分 | Blueprint | アプリのみの意味での「Blueprint」 | 列は無い（顧客限定の教材の割当で結果的に区別している） | 確定 |
| （通常の区分） | コーパス教材を作らず、汎用教材を使う契約の区分 | — | — | 列は無い | 未決 |

| **ライブセッション付き** | ライブセッションのセッション数が付く契約の利用形態 | With live sessions | ライブ付き・ライブ契約・ライブプラン・コーチ付き | `com_m_contract.contract_type = 2` | 確定 |

| **契約** | 顧客との1回分の取り決め（期間・ライセンス数・利用形態） | Contract | — | `com_m_contract`（`contract_name` は運営用の管理名、`plan_name` が生徒・コーチに見せる名前） | 確定 |

- 顧客は実質的にはテナント（生徒の所属の単位）。契約の相手の企業でないものも顧客として持つ（例: Webトライアルの申込者は固定の顧客「Webトライアル」に属し、本契約に進む場合は個人の顧客を作る）。それでも言葉は「顧客」にそろえる。
- 「初期テナント」は `client_type = 0` の名前としてだけ使う。

## 3. トレーニング・教材

| 使う言葉 | 定義 | 英語 | 使わない言い方 | DB・コード | 状態 |
|---|---|---|---|---|---|
| **NLT（Neuro-Language Training）** | トレーニング・教材作成の方法論。汎用教材・コーパス教材のどちらも NLT に準拠し、ダイアログ・ビデオも NLT の考え方に基づく | Neuro-Language Training | トレーニングの区分・教材の種類の名前としての NLT | — | 確定 |
| **自主トレーニング** | 生徒がアプリで1人で行うトレーニング | Self-training | 自主トレ・セルフトレーニング・NLT | 生徒アプリの「トレーニング」タブ | 確定 |
| **ライブセッション** | コーチと1対1で行うオンラインのセッション | Live session | レッスン・コーチング・セッション（単独で） | `com_t_session` | 確定 |
| **汎用教材** | 特定の顧客に依らず作った教材 | Generic content | 共通教材 | スプリントは `metadata.sprint_type = '0'`（`packages/types/content.ts`） | 確定 |
| **コーパス教材** | 顧客の IP 資産から作った単語・フレーズに基づく教材。Blueprint の契約で使う | Corpus content | 自社教材・カスタム教材・顧客専用教材 | スプリントは `sprint_type = '1'`、ダイアログは分類 `Corpus`（`category_id = 4`） | 確定 |
| **公開範囲：全体公開 / 顧客限定** | 教材を誰に見せるか。全体公開はすべての顧客、顧客限定は許可した顧客だけ | Public / Client-limited | クライアント限定 | `com_m_contents.content_scope`（0 / 1）、許可は `com_m_contents_access` | 確定 |
| **教材の種類** | 単語帳・スプリント・ダイアログ・ビデオ | — | — | `com_m_contents.content_type`、表示名は `packages/lib/content/ui.ts` | 確定 |
| **問題種類** | スプリントの問題の種類。UG Speed / UG Builders / UG Structure / UG Mastery の4つ | 同左 | Structure・Mastery（UG を省いた形）・UG Master | `QUESTION_TYPES`（`packages/types/sprint.ts`） | 確定 |
| **今日のトレーニングメニュー** | 生徒ごと・日ごとの自主トレーニングのやることの並び。ホームの主役に出す | Today's training menu | 今日やること（ホームの主役の名前として）・RunNow（旧システムの名前） | `student_t_training_menu` / `student_t_training_menu_item` | 確定 |
| **標準メニュー** | 今日のトレーニングメニューの中身のうち、旧システムのメニューを引き継いで決まりで組むもの（スプリント2種類＋発音トレーニングのビデオ）。コースに参加していない生徒に出す | Standard menu | — | `menu_source = 1`（`TRAINING_MENU_SOURCE.STANDARD`） | 仮置き |
| **タイムアタック / ドリル** | スプリントの2つのやり方（制限時間あり / なし）。「スプリント」は教材の種類の名前にだけ使う | — | スプリント（やり方の名前として） | `mode: 'sprint' \| 'drill'`、表示名は `SPRINT_MODE_LABEL` | 確定 |

- **出どころと公開範囲は別の軸**。「顧客限定＝コーパス教材」ではない。法人ごとに割り当てを変えるために、汎用教材を顧客限定にすることがある。
- 「コーチング」は、コーチの評価の項目（Coaching）と「月次コーチングレポート」の名前としては使ってよい。

## 4. 今の表記との差

確定した言葉と違う表記が残っている箇所。§5 が決まった後に、まとめて直す。

| 箇所 | 今の表記 | 直す先 |
|---|---|---|
| `com_m_contract` / `com_m_contract_plan` の `contract_type` の列のコメント | 1: Blueprintのみ, 2: Blueprint+ライブセッション | 1: アプリのみ, 2: ライブセッション付き |
| admin のライブセッションの有無の選択肢（`hasCoachNo`） | 無し（Blueprintのみ）/ None (Blueprint only) | 無し（アプリのみ）/ None (App only) |
| アプリ名（ページのタイトル・メールのテンプレート・コーチポータル名・Webトライアルの画面） | Gabby Blueprint | §5 の 1 で決まった名前 |
| `docs/`・`testing/` の文書 | ライブ付き・ライブ契約・共通教材・顧客専用・レッスン 等 | §2・§3 の「使う言葉」 |
