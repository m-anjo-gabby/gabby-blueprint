# 要望・不具合の受付台帳

運営スタッフは受付フォームから要望・不具合を送り、回答は受付台帳（スプレッドシート）のシート「受付台帳」に1行ずつ入る。ID は [../reference/drive-map.md](../reference/drive-map.md)。

## 台帳の列

| 列 | 中身 | 書く人 |
|---|---|---|
| A〜J | 受付日時・メールアドレス・ご連絡の種類・緊急度・対象のアプリ・画面・機能・起きた日時・対象の利用者・内容・補足資料のフォルダのリンク | フォーム（自動） |
| K | 状態（未対応 / 対応中 / 確認待ち / 対応済み / 見送り。プルダウン・色分けあり） | 開発チーム |
| L | 担当 | 開発チーム |
| M・N | 対応予定日・完了日（日付のみ） | 開発チーム |
| O | 対応メモ | 開発チーム |
| P | 関連する案件（開発側の案件・課題の番号やリンク） | 開発チーム |

列の位置はフォームの質問を変えると動くため、作業の前に1行目を読んで確かめる。

## 台帳を確認する

1. Sheets の `get_values` で `受付台帳!A1:P1000` を読み、状態が空欄・「未対応」の行と、緊急度が「至急」の行を挙げる。
2. 各行の内容を要約してユーザーに報告する。不具合は、関係しそうな画面・機能を `docs/screens/`・ソースで確かめ、原因の見当を添える（推測は推測と書く）。
3. 補足資料のリンクがある場合、中身を見る必要があれば Drive で読む。個人情報を報告に書き写さない。

## 対応状況を記入する

- ユーザーの指示があったときだけ書く（状態・担当を勝手に決めない）。
- Sheets の `update_values` で K〜P 列の該当セルだけを書く。A〜J 列（回答）は書き換えない。
- 状態は5つの値のどれかをそのまま書く（プルダウンの値と違う文字は入らない）。日付は `YYYY-MM-DD`。

## フォームを変える

1. 変える内容を決め、Apps Script の関数を書いてユーザーに実行してもらう（[../reference/known-limits.md](../reference/known-limits.md)）。今のフォームの作り方は [../scripts/request-form.gs](../scripts/request-form.gs) にあり、変えたらこのファイルにも反映する。
2. 実行後、台帳の1行目を読み、次を確かめる。
   - 新しい列が回答の列の最後に入り、管理用の列（状態〜関連する案件）がその右にそろっていること。
   - 状態のプルダウン・色分け、日付のチェックが「状態」「対応予定日」「完了日」の列に付いていること（`get_spreadsheet` で `dataValidation`・`conditionalFormats` を読む）。
   - A1:B1 が英語に戻っていたら「受付日時」「メールアドレス」に直す。
3. 消した質問の列が残っていたら、回答が無いことを確かめて列を削除する。
4. 「はじめにお読みください」の「要望・不具合のご連絡」の箇条書きをフォームに合わせる（[update-guide.md](update-guide.md)）。

## 行を広げる

プルダウン・日付チェック・色分けは1000行目までしか付いていない。回答が1000件に近づいたら、Sheets の `update_spreadsheet` で次をまとめて行う。

- `appendDimension` で行を足す。
- 状態の列に `setDataValidation`（`ONE_OF_LIST`、5つの値、`strict`・`showCustomUi`）、対応予定日・完了日に `DATE_IS_VALID` と表示形式 `yyyy-mm-dd`。
- 色分けの5つの規則を消して、同じ規則を新しい行数まで付け直す。
