# 固定アカウント・環境前提カタログ

## 固定アカウント と 都度シードの使い分け

| | 固定アカウント（本ファイル） | 都度シード（`testing/features/branches/`方式） |
|---|---|---|
| 用途 | ロールの基本的な振る舞いの確認、**過去タームの契約・学習履歴が必要な検証**（モニタリング等）、ブラウザでの手動確認の土台 | 機能追加・改修時の特定シナリオ、新規アカウント特有のケース（契約なし、コーチ交代等） |
| 生存期間 | 恒久的（削除しない。再投入のたびに履歴が蓄積される） | ブランチ検証単位（`${TAG}`付き、テスト完了後に削除） |
| 命名 | メール `qa-<role>-<seq>@gabby-qa-test.example`、顧客 `【QA固定】…` | メール `${TAG}-<用途>@gabby-qa-test.example`、顧客 `【QAテスト】…（${TAG}）` |

**命名で固定/使い捨てを機械的に区別する**（一括削除スクリプトがこの規則で対象を判定するため厳守する）:
`qa-` で始まるメール・`【QA固定】`で始まる顧客は固定、それ以外の `@gabby-qa-test.example` のメール・
`【QAテスト】`で始まる顧客は使い捨て。`${TAG}` に `qa` で始まる文字列を使わないこと。

**重要**: 固定アカウントは「いつ誰が使っても同じ前提で動く」ことが価値なので、状態を破壊する
操作（チケット消化、キャンセル、契約状態の変更等）を伴うテストは固定アカウントに対して
直接行わない。そのようなテストは都度シードのアカウントを使うか、固定アカウントを使う場合は
テスト後に作成・変更した行を元に戻す（例: `feature-20260918-dev/dialogue-practice-verify.ts` は
固定の担当関係を使い、作成した割当・進捗・履歴を最後に削除する）。

## 運用スクリプト（`testing/features/fixtures/`）

| スクリプト | 用途 |
|---|---|
| `seed-fixed-accounts.ts` | 固定アカウント・契約・学習履歴の投入（冪等。不足分のみ補完する）。**タームが変わったら（3か月ごと）再実行する** |
| `inventory-qa-data.ts` | QAデータの棚卸し（読み取り専用）。固定/使い捨ての残存状況を一覧表示する |
| `purge-disposable-qa-data.sql` | 使い捨てQAデータの一括削除（固定は対象外）。非QAデータにまたがる場合は中止する安全装置付き。Management API経由（`supabase/release/env/.env.<env>`のトークン）で実行する。末尾を例外で終わらせればdry-runになる |

| 環境 | 投入状況 |
|---|---|
| staging | 投入済み（2026-09-24。下記すべて） |
| dev | 投入済み（2026-09-26。現行スクリプトで再実行。`qa-student-01` の当期ライセンスは旧版スクリプト投入分と期間が重なるためスキップ） |

## ターム（契約期間）

固定アカウントの契約・ライセンスは、2026-06-01(JST)を起点とする**3か月単位のターム**で管理する
（T0=2026-06-01〜08-31, T1=09-01〜11-30, T2=12-01〜2027-02-28, …。計算は`testing/helpers/fixture-terms.ts`）。
実行日を含むタームを「当期」とし、`seed-fixed-accounts.ts`は前期・当期・次期の不足分だけを作る。
過去タームの契約・学習履歴は削除しないため、定期的に再投入するほど「過去分」のデータが蓄積される。

- ライセンスの日付は管理画面と同じくJSTの日境界（00:00:00.000〜23:59:59.999 JST）をUTCで保存する。
- 契約はタームごとに1件（`note`が`【QA固定】<プランコード> T<n>（期間）`）。アプリのみ契約は全生徒で共用、ライブ契約は生徒01専用。
- 学習履歴は各月10日（JST）に単語ドリル・スプリント・スプリントドリルを1件ずつ（実行日より未来の月は作らない）。

## テナント（`com_m_client`）

- クライアント名: `【QA固定】E2E/データ主体共通アカウント`（生徒・コーチはここに所属。アドミンは所属なし）
- 環境に共通公開の単語/スプリント教材が無い場合、学習履歴に使う限定公開教材へのアクセス権
  （`com_m_contents_access`）をこのテナントに付与する（`seed-fixed-accounts.ts`が自動で行う）。

## コーチペルソナ（タイムゾーン・Availability）

`com_m_user.timezone`（IANA名）と`com_m_coach_availability`（週次繰り返しの対応可能時間帯、
コーチのローカル時刻basis）で表現する。国籍・拠点は仕様上のデータ項目ではなく、ペルソナを
区別するための命名上の設定。

| アカウント | 拠点 / timezone | Availability（現地時刻） |
|---|---|---|
| qa-coach-ca-01 | バンクーバー / `America/Vancouver` | 月・水・金 18:00〜22:00（平日夜間中心） |
| qa-coach-us-01 | ニューヨーク / `America/New_York` | 火・木 10:00〜16:00（平日昼間中心） |

## 対象ブラウザ・デバイス（E2E）

| OS | ブラウザ |
|---|---|
| Windows | Chrome, Edge |
| Mac | Chrome, Safari, Edge |
| モバイル（Android/iOS） | Chrome, Safari, Edge |

**Playwright実装時の注意（着手時に判断すればよい先読み情報）**: PlaywrightのブラウザエンジンはChromium/Firefox/WebKitの3種類のみで、「Safari」「Edge」という名前のエンジンは無い。実務上は
Edge = Chromiumを`channel: 'msedge'`で起動、Safari = WebKitエンジンで近似（実機Safariそのものではない）という対応になる。モバイルは`devices['iPhone 14']`等のデバイスエミュレーションが基本で、実機に近い検証をしたい場合はBrowserStack等の実機クラウドとの併用を検討する。どこまで厳密にやるかはPlaywright着手時に相談する。
