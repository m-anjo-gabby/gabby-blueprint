# アドミンのライブセッション運用対応（代理キャンセル・予約し直し・コーチ交代・直接マッチング・回数の調整）

## 概要

- 対象ロール: アドミン（運営）、生徒、コーチ（交代前・交代後）
- なぜ重要か: 生徒・コーチから運営へ連絡が来たときに、アドミンがライブセッション管理の画面で代わりに日程・担当を直す業務。承認を挟まずその場で確定し、生徒・コーチへの通知も出さないため、回数の扱い（返還・交代前に使った回の差し引き・例外の追加）を誤ると、契約の回数が合わないまま誰も気づかない。
- 前後のジャーニー: 担当の成立は [生徒の初日](./student-first-day.md) の手順8。生徒・コーチ自身が日程を変える通常の流れは [ライブセッションの日程変更](./live-session-reschedule.md)。
- E2E: [tests/journeys/admin-live-session-ops.spec.ts](../tests/journeys/admin-live-session-ops.spec.ts)（手順1〜8）

## 業務ルール

- アドミンの代理操作は承認を挟まずその場で確定し、生徒・コーチへアプリ内通知もメールも送らない（運営が個別に連絡する）。例外は、直接マッチングの成立時に新しいコーチの名義で送られる挨拶のチャット（チャットの新着として通知される）。
- 代理キャンセルは返還するかをアドミンが選ぶ。返還した回は未割当に戻り、同じ枠で予約し直せる。コーチ交代でキャンセルされた回も未割当の数に入らない（返還扱い）。
- コーチ交代の後の直接マッチング・再申請の目標回数は、契約の枠の回数から、交代前の同じ枠で使った回（実施済み・予約済み・返還なしのキャンセル）を差し引いた数（`fn_matching_slot_target_sessions`）。
- 代理予約・直接マッチングが確かめるのは、コーチ・生徒の既存の予定との重なりだけ。コーチが登録した空き時間の外でも予約・成立する（アドミンの例外措置として縛らない。画面の注記で事前にコーチへ確認するよう案内する）。
