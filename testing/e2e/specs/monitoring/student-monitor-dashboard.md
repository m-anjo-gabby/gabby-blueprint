# 生徒モニタリングダッシュボード（モニターロール限定の横断閲覧）

## 概要

モニターロールを持つ生徒が、同じ契約先（クライアント）に所属する他の受講生の学習状況を
横断的に閲覧できる機能。アクセスできるのはモニターロールを持つ生徒のみであり、それ以外の
生徒はナビゲーションの「モニター」タブも表示されず、URL直接アクセスも遮断される。

## 関与ロール・画面

| ロール | 画面 | パス | 主なコンポーネント/アクション |
|---|---|---|---|
| 生徒（モニターロール保有） | アプリシェルのナビゲーション | apps/student `(shell)`配下の全画面 | `monitor`ロール判定により「モニター」タブを表示（モバイル=ボトムタブ／PC=サイドナビ） |
| 生徒（モニターロール保有） | モニタリングダッシュボード | apps/student `/monitor` | 画面仕様: [docs/screens/student/monitor.md](../../../../docs/screens/student/monitor.md) |
| 生徒（モニターロール非保有） | （アクセス不可） | apps/student `/monitor` | `apps/student/proxy.ts`のC-1判定により`/dashboard`へリダイレクトされる |

## 前提条件

- モニターロール保有の生徒アカウントが必要（`com_t_user_role`に`role_id='monitor'`の行を持つ
  こと）。固定アカウントはまだ無いため[`../../FIXTURES.md`](../../FIXTURES.md)に追加予定
  （未投入。実行前に都度ロールを付与するか、投入スクリプトを拡張する）。
- ロール変更（`com_t_user_role`への追加）はJWTの`app_metadata.roles`に即時反映されない
  可能性がある（`packages/lib/proxy-base.ts`がJWTクレームから`roles`を読む構成のため）。
  ロール付与後は再サインインしてから検証すること。
- 同一クライアントに、対象月で有効なライセンスを持つ他の受講生が最低1名必要（正常系で
  「対象生徒が出力される」ことを確認するため）。固定アカウントの`qa-student-01`
  （同一の【QA固定】クライアント所属、常時有効な週1回契約）を利用できる。
- デモユーザー（`role_id='demo_user'`）・別のモニターロール保有ユーザーが同一クライアントに
  いると、「モニターを含める」トグルの検証がしやすい（無ければ都度シード）。

## フロー（正常系）

1. モニターロールを持つ生徒がログインし、ナビゲーションに「モニター」タブが
   表示されていることを確認する
2. タブから`/monitor`へ遷移する（URLを直接開いてもモニターロールがあるためブロックされない）
3. 受講生サマリービューに、同一クライアントの受講生のうち対象年月に有効なライセンスを持つ人
   のみが一覧表示される
   - デモユーザー・モニターロール保有ユーザーは、「モニターを含める」トグルがOFFの間は
     一覧から除外される
   - 招待中・承認待ちユーザー（ライセンス未発行）は表示されない
4. 「モニターを含める」トグルをONにすると、デモユーザーを除く全員（モニターロール保有
   ユーザーも含む）が一覧に加わる
5. 対象年月の前月/次月ボタン、または年月ラベルをタップして開く年月ピッカーで他の月へ遷移する
   - 対象生徒が0人の月に遷移しても、コントロールバー（月送りボタン・年月ピッカー・
     CSVボタン）は表示され続ける
   - 前期のみ契約し当月は契約していない受講生も、その在籍期間が含まれる月を表示している間は
     一覧に現れる
6. 「単語ドリル履歴」「スプリント履歴」タブに切り替え、対象期間・受講生で絞り込んだ
   実績ログを確認する
7. CSVエクスポートボタンで、現在の絞り込み条件に基づく一覧をダウンロードする

## 異常系・バリデーション一覧

発生層の凡例は[README.md](../../README.md)参照。

| # | 条件 | 期待結果 | 発生層 |
|---|---|---|---|
| 1 | モニターロールを持たない生徒がダッシュボードを開く | ナビゲーションに「モニター」タブが表示されない | UI |
| 2 | モニターロールを持たない生徒が`/monitor`（またはそのサブパス、例: `/monitor?view=word`）へ直接URLアクセスする | `/dashboard`へリダイレクトされる（`apps/student/proxy.ts`のC-1、前方一致判定） | 両方（UI: 導線非表示／サーバー: proxyでリダイレクト） |
| 3 | 表示中の対象年月に、有効なライセンス期間が重なる受講生が1人もいない | 一覧は0件だが、コントロールバー（月送りボタン・年月ピッカー・CSVボタン）は表示されたまま。「この年月に該当する受講生が見つかりません」を表示（モニター未含の場合は「モニターを含める」をONにする案内も併記） | UI |
| 4 | 招待中・承認待ちユーザー（`com_t_invitation`、本登録未完了＝ライセンス未発行）が同一クライアントにいる | 一覧・絞り込み・実績のいずれにも一切表示されない | RPC |
| 5 | 停止(status=0)・満了(status=9)のライセンスのみが対象期間と重なっている受講生がいる | 対象外（status=1の有効なライセンスのみが判定対象） | RPC |
| 6 | デモユーザー（`role_id='demo_user'`）が同一クライアントにいる | 「モニターを含める」の状態に関わらず常に一覧・実績から除外される | RPC |

## E2Eテストケース候補

| 優先度 | シナリオ | 概要 |
|---|---|---|
| 高 | モニターロール_正常アクセスと対象生徒出力 | モニターロール保有生徒でログイン→「モニター」タブから`/monitor`へ→同一クライアントの対象生徒一覧が出力される |
| 高 | モニターロール無し_アクセス拒否 | モニターロールを持たない生徒でログイン→ナビゲーションに「モニター」タブが無いことを確認→URL直接アクセスは`/dashboard`へリダイレクトされる |
| 中 | モニターを含めるトグル | OFFではモニターロール保有ユーザーが一覧から除外され、ONで表示される |
| 中 | 対象年月0件でもコントロールバー表示 | 対象生徒がいない月へ遷移→一覧は空だが月送りボタン・年月ピッカー・CSVボタンは表示されたまま |
| 中 | 年月ピッカーでの直接ジャンプ | 年月ラベルをタップ→ピッカーで別の年月を選択→一覧が切り替わる。「今月に戻る」で当月に戻る |
| 低 | CSVエクスポート | 一覧表示中にCSVボタンを押下→ダウンロードされたファイルに一覧内容が反映されている |
