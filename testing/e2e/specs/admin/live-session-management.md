# ライブセッション管理（アドミン代理操作）

## 概要

管理者が顧客・生徒・契約（チケット）を選択し、その生徒のライブセッション予約状況・担当コーチ
割当を確認した上で、生徒・コーチに代わって「セッションのキャンセル」「未消化チケットでの予約」
「担当コーチの交代」「コーチとの直接マッチング」「コマ単位のセッション数個別調整」を行う。
いずれも承認ステップを挟まず即座に確定する管理者専用の代理操作。

| ロール | 画面 | パス | 主なコンポーネント/アクション |
|---|---|---|---|
| アドミン | ライブセッション管理 | `admin` `/live-sessions` | `LiveSessionManagementView.tsx`。画面仕様: [docs/screens/admin/live-sessions.md](../../../../docs/screens/admin/live-sessions.md) |

## 前提条件

- アドミンアカウント: [`../../FIXTURES.md`](../../FIXTURES.md)の`qa-admin@gabby-qa-test.example`で足りる。
- 対象の生徒: ライブセッション付き契約（`com_t_user_session_ticket`を伴う契約）を1件以上保有していること。固定アカウントには現状ライブセッション契約を持つものが無いため、`testing/features/branches/`方式で都度シードする（`admin_match_student_with_coach`経由で定期スケジュール枠を作成するのが最短）。
- コーチ交代・直接マッチングの検証には、担当コーチとは別のコーチアカウントが必要。

## フロー（正常系）

1. アドミンが顧客を選択する。生徒セレクトの選択肢が読み込まれる。
2. アドミンが生徒を選択する。その生徒が保有するライブセッション付き契約（現在・過去とも）が読み込まれ、現在有効な契約があれば自動選択される。
3. アドミンが契約（チケット）を選択する。定期スケジュール枠一覧（全n枠中 稼働n枠・未割当n枠のサマリー付き）とセッション一覧（今後の予定／実施済み／変更履歴タブ）が表示される。
4. 4a. 未割当の枠番号に対し「直接マッチング」→ コーチ・曜日・開始時刻を指定して実行 → `admin_match_student_with_coach`により即座にマッチング成立、セッションも自動生成される。
   4b. 稼働中の枠に未割当チケット枠（shortfall）がある場合「セッションを予約」→ 日付・開始時刻を指定して実行 → `admin_book_session_direct`により即座にセッション行が作成される。
   4c. 稼働中の枠で「セッション数を調整」→ 新しい総セッション数（現在値より大きい値）・理由を入力して実行 → `admin_adjust_schedule_target_sessions`によりその枠の`target_sessions`のみ引き上げられる（契約全体の`total_sessions`は変更しない）。新しいセッションは自動生成されず、shortfallが増えることで4bの「セッションを予約」で追加予約できるようになる。
   4d. 稼働中の枠で「コーチ交代」→ 確認ダイアログで実行 → `release_lesson_schedule_slot`によりその枠が終了(status=9)し、未実施の今後のセッションはキャンセルされる。実施済みのセッション結果・チャット・宿題は削除されない。
   4e. セッション一覧の「今後の予定」タブから「キャンセル」→ 返還有無チェックボックス・理由を指定して実行 → `cancel_session`（`p_as_admin: true`）により即座にキャンセルされる。
5. いずれの操作後も、選択中の顧客・生徒・契約の状態は維持されたまま、対象契約の枠・セッション一覧のみが再取得される。

## 異常系・バリデーション一覧

| # | 条件 | 期待結果 | 発生層 |
|---|---|---|---|
| 1 | 生徒未選択のまま契約セレクトを開こうとする | 非活性セレクトに「生徒を選択してください」表示 | UI |
| 2 | 選択した生徒がライブセッション付き契約を保有しない | 「この生徒はライブセッション付き契約を保有していません」表示 | UI |
| 3 | 過去契約（`is_current=false`）を選択する | 「過去契約（参照のみ）」バッジを表示し、キャンセル・予約・調整・コーチ交代・直接マッチングの操作ボタンを一切表示しない | UI |
| 4 | 直接マッチングで既にリクエスト/マッチングが存在する枠番号を指定する | 一意制約違反(23505)を「この枠には既にリクエストまたはマッチングが存在します」に変換して表示 | 両方 |
| 5 | 直接マッチングでコーチの空き時間・既存予定と重複する日時を指定する | 「このコーチは指定の時間帯に既に別の予定があります」表示 | RPC |
| 6 | セッション予約でコーチの空き時間外の日時を指定する | サーバー側でエラー | RPC |
| 7 | セッション数調整で現在値と同じ値を指定する | `new target_sessions (%) must be greater than current (%)`で拒否 | RPC（UI導線なし。UI側はボタン押下前の`min`属性で未満値の入力自体は抑止するが、同値の送信はブロックしない） |
| 8 | セッション数調整で現在値未満の値を指定する | 同上（#7と同じ検証） | 両方（UIは`min`属性で入力を抑止、RPCが最終検証） |
| 9 | セッション数調整で理由を空欄のまま実行しようとする | UI側で確定ボタンが非活性（送信不可） | UI |
| 10 | セッション数調整で理由が空白のみの値をRPCに直接送る | `reason is required`で拒否（`btrim`による前後空白除去） | RPC（UI導線なし。UI側は`.trim()`チェックがあるため通常到達しない） |
| 11 | セッション数調整で一時停止・終了済みの枠に対して実行する | `cannot adjust target_sessions on a non-active schedule slot`で拒否 | RPC（UI導線なし。UI側は稼働中の枠にのみボタンを表示するため通常到達しない） |
| 12 | セッション数調整を生徒本人・コーチ本人のJWTで直接RPC実行する | `not authorized to adjust target sessions`で拒否 | RPC（UI導線なし。管理画面はアドミンのみアクセス可能） |
| 13 | コーチ交代・キャンセル・予約・調整のいずれかの代理操作後 | 選択中の顧客・生徒・契約は維持され、再選択不要（対象契約の枠・セッション一覧のみ再取得） | UI |

## E2Eテストケース候補

| 優先度 | シナリオ | 概要 |
|---|---|---|
| 高 | 顧客→生徒→契約の絞り込みで対象を正しく特定できる | 3段階セレクトの連動・自動選択（現在有効契約優先）を確認 |
| 高 | セッション数調整で総セッション数を引き上げ、未割当枠バッジが増え「セッションを予約」で追加予約できる | #4c→4bの連続フロー。フォーム再検証（データ主体テストで既に検証済み: `testing/features/branches/feature-20260918-dev/target-sessions-adjustment.feature`） |
| 高 | 代理キャンセル・予約・直接マッチング・コーチ交代それぞれが即座に反映される | 各操作後の一覧再表示を確認 |
| 中 | 過去契約選択時に操作ボタンが一切表示されないこと | 参照専用であることの確認 |
| 中 | セッション数調整ダイアログの確定ボタンが、値・理由未入力時に非活性であること | UI側バリデーションの確認 |
| 低 | 代理操作後も顧客・生徒・契約の選択状態が維持されること | revalidatePath起因の状態リセット不具合（修正済み）の回帰確認 |
