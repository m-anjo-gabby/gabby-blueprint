# 削除・使用の停止（アドミン）

## 概要

アドミンが、ユーザー・顧客・マスタ・教材・イベントを「使用をやめる」「誤登録を取り消す」「退会させる」「顧客ごと削除する」。
規約の正本は [docs/DATA-DELETION.md](../../../../docs/DATA-DELETION.md)（論理削除の列は持たない。業務の記録がある行は物理削除できず、使用をやめる操作を案内する）。

| 操作 | 種類（規約の §1） | 戻せるか |
|---|---|---|
| ユーザーの停止・再開 | A. 使用をやめる | 戻せる |
| 顧客の取引状態（取引中・取引終了）、プランの販売中、タイムゾーンの使用中、教材の公開状態 | A. 使用をやめる | 戻せる |
| プラン・タイムゾーン・教材・ダイアログのセッション明細・顧客の削除 | B. 誤登録の取り消し（業務の記録があれば拒否） | 戻せない |
| ユーザーの退会 | C. 退会（個人情報の消去） | 戻せない |
| 顧客の削除（DangerZone） | D. 顧客単位の一括削除 | 戻せない |

## 前提条件

- アドミンアカウント: [`../../FIXTURES.md`](../../../FIXTURES.md) の `qa-admin@gabby-qa-test.example`（`admin` ロール。退会・顧客の削除はシステム管理者だけが実行できる）。
- 状態を変える・消すため、使い捨ての顧客・生徒・プランで検証する（`support/authFixtures.ts`）。固定のマスタ（実際のタイムゾーン・プラン）は消さない。
- 退会は、有効なライセンス・今後のセッション・回答待ちの申請・稼働中の定期予定が無いことが条件（先に停止・キャンセルする）。

## フロー（正常系）

1. **停止・再開**: ユーザー詳細の「利用を停止する」→ 確認 → 「利用を停止しました」。見出しの状態が「停止中」になり、そのユーザーはログインできない（`com_m_user.status` = 0、認証のアカウントの停止）。「利用を再開する」で戻る。
2. **退会**: DangerZone の「退会させる」→ 消えるもの・残るものの説明 → 表示名を入力 → 「退会させる」→ 「退会の処理が完了しました」。
   氏名は「退会済みユーザー」、状態は「退会済み」になり、認証のアカウント・正式氏名・お気に入り等が消える。ライセンス・セッション等の記録は残る（`fn_withdraw_user`）。
3. **顧客の取引状態**: 編集ダイアログの「取引状態」を取引終了にして保存 → 一覧の顧客名に「取引終了」の目印が付き、取引中の顧客の後ろに並ぶ。
4. **顧客の削除**: 編集ダイアログの最下部の「顧客を削除する」→ 消える件数（生徒・コーチ・招待中・契約・ライセンス・セッション・学習の記録・チャット・お知らせ・イベント）を表示 →
   顧客名を入力 → 「顧客を削除する」→ 「顧客を削除しました」。顧客・所属するユーザー（認証のアカウントを含む）・契約・ライセンス等が消え、削除の記録（`com_t_data_deletion_log`）が残る（`fn_purge_client`）。
5. **販売中・使用中**: プラン・タイムゾーンの編集で「販売中」「使用中」をオフにする → 一覧に「販売終了」「使用停止」の目印が付き、契約の作成・タイムゾーンの選択肢に出なくなる（編集中の契約が使っているプランは残る）。
6. **教材の公開状態**: 教材の編集で「公開状態」を非公開にする → 一覧に「非公開」の目印が付き、生徒・コーチに表示されなくなる（`com_m_contents.status`）。新規作成時は非公開。
7. **誤登録の取り消し**: 使われていないプラン・タイムゾーン等は一覧の削除ボタンで削除できる（取り消せない）。

## 異常系・バリデーション一覧

| # | 条件 | 期待結果 | 発生層 |
|---|---|---|---|
| 1 | 有効なライセンスがあるユーザーを退会させる | 「有効なライセンスがあります。先にライセンスを停止してください」と表示し、何も消さない | DB（`fn_withdraw_user` の `active_license`） |
| 2 | 今後のセッション・回答待ちの申請・稼働中の定期予定があるユーザーを退会させる | それぞれ「今後のセッションがあります…」「回答待ちの申請または稼働中の定期予定があります…」 | DB（`scheduled_session` / `active_matching`） |
| 3 | 退会・顧客の削除で入力した名前が一致しない | 実行のボタンが押せない（サーバーでも `name_mismatch` で拒否） | 両方 |
| 4 | 退会の途中で失敗した（Storage・認証のアカウントの削除） | もう一度実行すると続きから終わる（退会済みでも残りを消す。名前の照合はしない） | サーバーアクション |
| 5 | 初期テナント・Webトライアルの顧客を削除する | 件数の代わりに「この顧客（初期テナント・Webトライアル）は削除できません」を表示し、実行できない | DB（`protected_client`） |
| 6 | 管理者が所属する顧客、他の顧客のユーザーとのセッション・担当関係がある顧客を削除する | 「管理者が所属しているため…」「他の顧客のユーザーとのセッション・担当関係等があるため…」 | DB（`has_admin` / `linked_to_other_client`） |
| 7 | 契約で使われているプランを削除する | 「契約で使われているため削除できません。編集で「販売中」をオフにしてください」。プランは消えない | DB（外部キーの RESTRICT。`isInUseError`） |
| 8 | ユーザー等が使っているタイムゾーンを削除する | 「ユーザー等が使っているため削除できません。編集で「使用中」をオフにしてください」 | DB（同上） |
| 9 | 進捗・会話の記録があるダイアログのセッション明細を削除する | 「進捗・会話の記録があるため削除できません」 | DB（同上） |
| 10 | 開催済み（開始日時を過ぎた）のイベントを削除する | 「開催済みのイベントは削除できません。参加の記録を残すため、編集で非公開にしてください」。イベントは消えない | サーバーアクション |
| 11 | 停止中・退会済みのユーザー | 代理ログインのボタンを出さない。退会済みには停止・再開・退会の操作を出さない | UI |
| 12 | `admin` ロールを持たない管理者が退会・顧客の削除・停止を実行する | 「システム管理者だけが実行できます」 | サーバーアクション（UI導線なし。画面自体が `admin` ロール限定） |

## 関連RPC・テーブル

- RPC: `fn_withdraw_user`（退会）、`fn_purge_client`（顧客単位の一括削除。`p_dry_run` で件数だけ）。どちらも service_role 専用
- テーブル: `com_m_user.status`（1:有効 / 0:停止 / 9:退会済み）、`com_m_client.status`（1:取引中 / 9:取引終了）、`com_m_contents.status`（1:公開 / 0:非公開）、
  `com_m_contract_plan.is_active` / `com_m_timezone.is_active` / `com_m_country.is_active` / `com_m_coach_specialty.is_active`、`com_t_data_deletion_log`、ビュー `vw_user_list.user_status`
- 実装参照: `apps/admin/actions/adminDataDeletionAction.ts`、`apps/admin/components/common/`（`DangerZone` / `TypedConfirmDialog` / `ActiveSwitchField` / `InactiveBadge`）、
  `packages/lib/supabase/pgErrors.ts`（`isInUseError`）、`packages/lib/storage/removeStorageFiles.ts`
- 確認スクリプト（RPC の中断条件・消えるもの・残るもの）: `testing/features/branches/feature-20261016-dev/data-deletion-check.ts`
