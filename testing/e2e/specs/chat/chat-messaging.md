# チャット（メッセージのやり取り・既読・添付）

## 概要

生徒・コーチ・運営が、1対1またはグループのルームでメッセージと添付ファイルをやり取りする。
1対1では相手が読んだ自分の最新の発言に既読を表示し、新着は開いている画面によらずナビの未読バッジへリアルタイムに反映する。
ルームへはアプリ内の一覧のほか、通知・メール等のリンクから直接開ける（未ログインならログイン後にそのルームへ戻る）。

## 前提条件

- ルームは、アドミンの作成またはマッチング成立時の自動開設で作られる（[admin/chat/list.md](../../../../docs/screens/admin/chat/list.md)）。
- E2E は固定アカウントの生徒01と担当外コーチUS01の間に、**テストごとに使い捨てのルーム**（1対1・グループ）を作り、終了後に削除する
  （`support/chatFixtures.ts`。ルーム名が `【QAテスト】チャットE2E` で始まる）。固定のチャットルーム（`seed-chat-rooms.ts`）の既読状態は変更しない。
- コーチ側の操作（送信・既読）は、実際にサインインしたコーチのJWTで行う。

## フロー（正常系）

1. 生徒がルームを開く（一覧から、またはリンクから直接）。開いた時点で未読があれば、最初の未読の上に「ここから未読」を表示し、その位置から表示する。
   開いたルームは最新メッセージまで既読になる。
2. 生徒がメッセージを送る（PCは Enter、スマートフォンは送信ボタン）。添付は、クリップアイコン・画像の貼り付け・タイムラインへのドロップで
   送信前の添付に加わり、送信ボタンで本文と一緒に送られる（貼り付け・ドロップだけでは送信されない）。
3. 相手（コーチ）がルームを開くと、生徒の画面で自分の最新の発言の下に「既読」が表示される（1対1のみ。リアルタイム）。
4. コーチが送ったメッセージは、生徒が開いているルームならタイムラインに、他の画面を開いていればナビの未読バッジに、リアルタイムで反映される。
5. 入力途中の本文・送信前の添付は、別のルームへ移って戻っても残る（ページの再読み込みで消える）。
6. 未ログインでルームのリンクを開くと `/login?next=/chat/<roomId>` へ移り、ログイン後にそのルームが開く。

## 異常系・バリデーション一覧

| # | 条件 | 期待結果 | 発生層 |
|---|---|---|---|
| 1 | 存在しない・参加していないルームのリンクを開く | 画面全体の404ではなく、右ペインに「このチャットは表示できません」と一覧へ戻る導線を表示 | UI |
| 2 | 10MBを超えるファイルを添付（クリップ・貼り付け・ドロップ共通） | エラー通知を出し、そのファイルだけ添付しない | UI |
| 3 | 文字と画像の両方が入ったクリップボードを貼り付け（Excel・Word 等からのコピー） | 文字の貼り付けを優先し、画像は添付しない | UI |
| 4 | ログイン画面の `?next=` に外部URL（`//example.com` 等）を指定 | 無視してホームへ移る | UI（proxy・サーバー） |
| 5 | グループ・アドミンの査閲モード | 既読表示を出さない。査閲で開いても参加者の既読にならない | UI |
