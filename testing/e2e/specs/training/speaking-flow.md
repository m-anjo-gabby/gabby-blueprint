# 発話の流れ（単語帳・スプリントの再生 → 発話評価）

## 概要

生徒の自主トレーニングで、音声を再生してから発話させ、自前の評価（`analyzePhrase`）で採点する流れ。
単語帳は発話ボタンで表示中のフレーズを発話する。スプリントは問題種別ごとに決まった順で音声を再生した後に発話する
（発話評価OFFでは発話しない）。スプリントのドリルモードは、単語帳と同じく発話ボタンで発話する。
発話評価は無料の Web Speech API の文字起こしを使う（従量課金の発音評価AIは使わない）。

| ロール | 画面 | パス | 主なコンポーネント/アクション |
|---|---|---|---|

## 前提条件

- アプリの利用権（ライセンス）があり、教材が公開されている生徒。E2E は使い捨てのアプリのみ契約の生徒を作る（[FIXTURES.md](../../../FIXTURES.md)）。
- スプリントは、4種別（Speed・Builders・Structure・Mastery）すべてに音声付きの問題がある教材を使う（環境によって公開範囲が違うため、名前ではなく問題の有無で選ぶ）。
- 発話評価ONのスプリントは、選択画面でマイクの許可（getUserMedia）が必要。
- E2E では実際のマイク・音声認識を使えないため、テスト用の認識方式（fake。参照文または指定の文字起こしを返す）に切り替える。
  fake は本番以外のビルドで `window.__gabbyFakeSpeech` を設定した場合だけ使われるため、dev でのみ検証する（[CONVENTIONS.md](../../CONVENTIONS.md) 2章、`KJ-2026-1003-04`）。

## フロー（正常系）

1. **単語帳**: 生徒が発話ボタン（「発話練習」）を押す → 開始チャイムが鳴り終わってから認識を開始する → 表示中のフレーズを参照文として評価し、評価（スコア・判定）を表示する。
   1a. 発話中にもう一度押す（「発話を止める」）と、その時点の評価で確定する。
   1b. 発話中にフレーズを切り替えると、評価を出さずに中断する。
2. **スプリント（スプリントモード・発話評価ON）**: 1問ごとに、問題種別に応じて音声を再生 → 開始チャイム → 認識 → 解答文を参照文として評価し、評価を一瞬表示して次の問題へ進む。
   - Speed: 質問文 → 発話（基本文は無い）。参照文は開始時に選んだ回答の種類（YES/NO）の解答文
   - Builders・Structure: 基本文 → 指示文 → 発話
   - Mastery: 基本文 → 質問文 → 発話
   2a. 発話評価OFF: 音声を再生した後は発話せず、「発話なし」の表示で生徒が「次の問題へ」を押して進める（脳内回答）。
3. **スプリント（ドリルモード）**: 問題の音声（基本文 → 質問文/指示文）を自動で再生する。発話はせず、生徒が発話ボタンを押すと開始チャイム → 認識 → 解答文で評価し、評価を表示する。評価の後に解答音声を再生する。

4. **中断と復旧**（iOS の放置・バックグラウンド・通話等）: 画面が隠れたら再生・発話を止めてマイクを放す。戻ったら自動で再開を試み、
   再生位置（`currentTime`）が進めば復旧として、スプリントは中断した問題を頭からやり直す（単語帳は自動再生をオフにする）。
   自動で再開できなければ「タップして再開」を出し、タップで壊れた AudioContext を作り直す。
   4a. タップでも復旧しない → 再読み込みを案内する。再読み込みした同じ画面でまた復旧しない → タブを閉じて開き直すよう案内する。

## 異常系・バリデーション一覧

| # | 条件 | 期待結果 | 発生層 |
|---|---|---|---|
| 1 | 発話中に停止ボタンを押す | その時点（何も聞き取れていなければ0点）の評価で確定する | UI |
| 2 | 発話中にカード（フレーズ・問題）を切り替える・スキップする・画面を離れる | 評価を出さずに中断し、前のカードの評価を後から反映しない | UI |
| 3 | 制限時間（10秒）まで発話が確定しない | 制限時間で、その時点の評価で確定する | UI |
| 4 | スプリントの問題の音声が再生できない | 通知の上でその問題をスキップし、回答履歴から除外する（ドリルは通知のみ） | UI |
| 5 | マイクが拒否されている | スプリントは発話評価OFFで実施する（脳内回答） | UI |
| 6 | 発話中に画面が隠れる（バックグラウンド・画面ロック） | 発話を止め、戻ると同じ問題を頭からやり直す（次の問題へ進まない） | UI |
| 7 | AudioContext が running なのに無音（iOS）・再生が終わらない | 音声の長さ＋余裕で打ち切り、「タップして再開」を出す（画面の流れを止めたままにしない） | UI（実機のみ） |
| 8 | タップでも復旧しない／再読み込み後も復旧しない | 再読み込み／タブを閉じて開き直す、をそれぞれ案内する | UI（実機のみ） |

## 関連RPC・テーブル

- RPC: なし（評価はブラウザ内。記録は各画面の進捗・結果の保存で行う）
- テーブル: `com_m_sprint_questions`（`statement_*`・`question_*`・`answer_sentence_yes/no_*`）、`self_t_sprint`（実施の記録。`answered_history` は問題ごとの回答の配列で、保存前に `packages/lib/sprint/answeredHistory.ts` で形を検証する）
- 実装参照: `packages/lib/audio/core/audioRuntime.ts`（中断・復旧の検知、再生位置による判定、打ち切りタイマー、発生状況の記録 `audio:*`）、
  `apps/student/components/common/AudioResumeBanner.tsx`（再開・失敗の案内）、`AudioDiagnosticsReporter.tsx`（記録の送信）、
  `packages/lib/audio/react/useSpeakingPlayer.ts`（再生→発話の共通プレイヤー）、`packages/lib/audio/core/speechAssessment.ts`（発話評価）、
  `packages/lib/audio/core/recognizer/`（認識方式: Web Speech API・fake）、`packages/lib/sprint/prompts.ts`（スプリントの再生順）、
  `packages/lib/assessment/native-speech.ts`（`analyzePhrase`）
- 用語（status値等）: [_GLOSSARY.md](../_GLOSSARY.md)

## E2Eテストケース候補

| 優先度 | シナリオ | 概要 |
|---|---|---|
| 高 | 単語帳の発話 | 発話ボタン → 表示中のフレーズで発話評価され、評価が表示される（フロー1。実装済み: [tests/training/speaking-flow.spec.ts](../../tests/training/speaking-flow.spec.ts)） |
| 高 | 単語帳の停止 | 発話中に止めると、その時点の評価で確定する（#1。実装済み: 同上） |
| 高 | スプリントの再生順（4種別） | Speed は質問文だけ、Builders・Structure は基本文 → 指示文、Mastery は基本文 → 質問文を再生した後に、同じ問題の解答文で発話評価される（フロー2。実装済み: 同上） |
| 高 | スプリントの発話評価OFF | 問題を再生した後は発話せず、「次の問題へ」で進める（フロー2a。実装済み: 同上） |
| 高 | ドリルの発話 | 問題の自動再生の後は発話せず、発話ボタンで解答文の発話評価が始まる（フロー3。実装済み: 同上） |
| 高 | 結果の保存と結果画面の再生 | スプリントの終了後、実施の記録が保存される（履歴は出題順に問題ごとのスキップの有無・発話評価のスコアを持ち、発話評価の件数が集計と一致する）。結果画面で「全て再生」が自動で始まる。文の個別再生では問題ごとの再生ボタンが「再生中」にならない（実装済み: 同上。画面仕様: [sprint-result.md](../../../../docs/screens/student/training/sprint-result.md)） |
| 高 | 中断と復旧 | 発話中に画面が隠れて戻ると、同じ問題を頭からやり直す（フロー4・#6。表示・非表示は擬似的に切り替える。実装済み: 同上） |
| 中 | 発話中の切り替え | 発話中にカードを切り替えると評価が出ない（#2） |
| 中 | Speed の NO 回答 | NO で開始すると NO の解答文で発話評価される |
| 低 | 音声の再生失敗 | 音声ファイルが取得できない問題はスキップされる（#4） |
